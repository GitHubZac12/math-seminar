# SANA Initiative Breast Cancer Risk Modeling Project

This folder contains a cleaned, validated Python workflow for exploratory breast-cancer mortality risk modeling in San Luis Potosí (SLP), Mexico. The current workflow builds a municipality-level analytic dataset, engineers environmental exposure features, fits baseline and Bayesian count models, and exports map/dashboard-ready outputs.

The final model in this package is a **Bayesian spatial hierarchical negative-binomial disease-mapping model**. It uses:

- municipality-level breast-cancer mortality counts,
- female population as the model offset,
- age-structure controls when available,
- geospatial environmental exposure covariates,
- a proper CAR structured spatial random effect based on municipality adjacency,
- an iid unstructured municipality effect,
- posterior predicted rates and credible intervals for all retained municipalities.

The outputs should be interpreted as **period-level mortality rates per 100,000 female population**, not annual rates, unless the source mortality file is later normalized by year.

Collect data from SANA-Initiative/BreastCancer-RiskPrediction \
From outside of the package root:

```bash
git clone https://github.com/SANA-Initiative/BreastCancer-RiskPrediction.git
```

Folder structure should appear as:
```text
BreastCancer-RiskPrediction/
  ...
sana-project/
  ...
```

From the package root:

```bash
pip install -r requirements.txt
```

**Note:** The `fiona` package is commented out in `requirements.txt` because it requires GDAL to be installed on your system. If you need advanced geospatial file I/O capabilities, install GDAL first (via conda or system package manager) then uncomment and install fiona:

```bash
# On conda:
conda install gdal
pip install fiona

# Or on Ubuntu/Debian:
sudo apt-get install gdal-bin libgdal-dev
pip install fiona
```

If PyMC installation is slow on your machine, you can still run the non-Bayesian pipeline first. The Bayesian commands require `pymc` and `arviz`.

## Full command sequence

Replace `/path/to/BreastCancer-RiskPrediction` with the path to the raw GitHub repository clone.

### 1. Run the main data/model pipeline

**PowerShell (Windows):**
```powershell
python -m src.run_pipeline --repo-root "C:\path\to\BreastCancer-RiskPrediction" --output-dir ./outputs --scope slp --missing-outcome-policy exclude --age-adjustment auto --top-k 10 --bootstrap-draws 100
```

**Bash/Unix:**
```bash
python -m src.run_pipeline \
  --repo-root /path/to/BreastCancer-RiskPrediction \
  --output-dir ./outputs \
  --scope slp \
  --missing-outcome-policy exclude \
  --age-adjustment auto \
  --top-k 10 \
  --bootstrap-draws 100
```

This creates the cleaned analytic dataset, exposure features, frequentist negative-binomial model, sensitivity models, Bayesian input files, spatial adjacency matrix, baseline map, and baseline risk cube.

If you need a faster run for a quick check, add `--skip-sensitivity` to skip the single-exposure-family sensitivity models, and/or reduce `--bootstrap-draws` from 100 to 10-20.

### 2. Validate baseline outputs

**PowerShell (Windows):**

## Main source files

### `src/run_pipeline.py`

Main workflow. It discovers raw data files, selects SLP inputs, builds the analytic dataset, engineers exposure features, fits the baseline negative-binomial model, runs sensitivity models, writes Bayesian inputs, builds spatial adjacency files, and exports map/risk-cube outputs.

### `src/io_utils.py`

File-loading and schema utilities. It standardizes column names, infers geography/population/outcome/coordinate columns, reads Excel/CSV/spatial files, and creates canonical municipality `geo_id` keys.

### `src/exposure_features.py`

Turns point-source environmental datasets into municipality-level features such as nearest-source distance, distance-kernel intensity, and counts within buffers.

### `src/modeling.py`

Frequentist negative-binomial modeling tools. It filters weak/duplicate/collinear features, standardizes predictors, fits the baseline model, predicts rates, and estimates top-K ranking stability using coefficient draws.

### `src/sensitivity.py`

Runs one model per exposure family, such as water-only, brick-kiln-only, mines/metals-only, and RETC-only models. This checks whether conclusions are sensitive to correlated exposure families.

### `src/risk_cube.py`

Creates dashboard-ready long-format risk tables and GeoJSON map outputs.

### `src/spatial_utils.py`

Builds the municipality adjacency matrix and neighbor table used by the spatial Bayesian model.

### `src/bayesian_nb_model.py`

Fits the non-spatial Bayesian negative-binomial model and exports posterior predicted rates.

### `src/bayesian_spatial_hierarchical_model.py`

Fits the Bayesian spatial hierarchical negative-binomial model with CAR structured effects and iid unstructured municipality effects. It can also merge Bayesian spatial summaries into the map and risk cube.

### `src/validate_outputs.py`

Checks whether outputs are internally consistent: population denominators, missing outcomes, feature filtering, adjacency, Bayesian input/config alignment, posterior rate intervals, sampler diagnostics, map outputs, and path portability.

## Interpretation guidance

Valid statements:

- The model estimates municipality-level period breast-cancer mortality risk per 100,000 female population.
- Bayesian outputs provide posterior means and credible intervals.
- Top-K probabilities summarize how likely each municipality is to fall in the high-risk group under model uncertainty.
- The spatial model borrows residual-risk information across adjacent municipalities.

Avoid these statements unless additional data are added:

- Do not call the rates annual unless year normalization is implemented.
- Do not make causal claims about contaminants.
- Do not claim manzana-level disease risk; current disease outcomes are modeled at municipality level.
- Do not interpret missing-outcome municipalities as true zero-outcome areas. They are excluded from the likelihood and retained for prediction.
